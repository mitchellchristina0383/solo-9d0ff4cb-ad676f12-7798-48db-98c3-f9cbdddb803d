# 内网 HTTPS 根证书更换顺序规划器

值班员更换内网 HTTPS 根证书时，用本工具先排好变更顺序：录入服务副本的新旧
PEM 证书链与终端批次的新旧 PEM 根证书包，工具用真实的 `openssl verify` 核验，
给出“每一步只换一个副本的链、或更新一批终端根包”的可行顺序；无解时区分
**证书材料无法通过验证** 与 **过渡名额不足** 两类原因并给出明细。

## 1. 模型与规则

| 对象 | 状态 | 单步动作 |
| --- | --- | --- |
| 服务副本（1~4 个） | 旧链 / 新链 | 一次只把一个副本从旧链切到新链 |
| 终端批次（1~4 批） | 旧包 / 过渡包（新旧并集）/ 新包 | 一批终端可旧包直跳新包，也可先切并集过渡，再切新包 |

- 页面可设置**同时处于过渡态的批次上限** L（0 表示禁止并集过渡，只能直跳）。
- 任一核验时刻（初始态及每步动作之后），每批终端都必须只用**当时持有的根
  证书包**，按域名验证每个副本**当时出示的证书链**；全部 “批次 × 副本”
  组合通过，该状态才合法。
- 核验调用本机 `openssl verify -no-CAfile -CAfile <根包> -untrusted <中间证书>
  -verify_hostname <域名>`：信任锚仅来自录入的根包（不加载系统默认 CA），
  同时完成链签名/有效期校验与 SAN 主机名校验。
- 状态空间至多 2⁴ × 3⁴ = 1296，BFS 求步数最少的方案，动作顺序固定
  （开过渡 → 换副本链 → 收过渡/直跳），方案可复现。
- 可选的 **OpenSSL 调用上限**（迁移页勾选启用，正整数）：
  - 每个“副本 × 链 × 批次 × 根包”核验格在整次请求内最多调用一次
    `openssl`，结果写入缓存全程复用——所有判定都按请求开始时刻的材料
    快照作出，同一格不会出现两种结论；
  - 调用次数用尽后未验格标记为“待核（未验）”，不写入缓存、不计为失败，
    依赖未验格的状态不入 BFS 队列；
  - 能确定当前名额下的最短方案、名额不足时的最小同时过渡批次数、或放开
    名额仍然无解时即**提前停验**；用尽次数且未验格仍可能改判时，结论
    标记为待定：已逐条核验通过的方案照常列出并注明“最短步数待定”，
    名额不足时给出已证实的名额下界；
  - 页面区分**通过 ✓ / 失败 ✗ / 未验？** 三态，并显示调用上限、实际调用
    次数与未验格数量。不启用上限时保持原行为（验完全部核验格）。
- 无解诊断：
  - **硬无解**：现状（旧链×旧包）或目标态（新链×新包）本身核验失败，或放开
    名额到全部批次仍走不通；页面列出每个失败的“批次 × 副本”在全部 6 种
    链/包组合下的 openssl 失败原因（含主机名不匹配时叶子实际 SAN）。
  - **过渡名额不足**：放开上限可解、按当前 L 不可解时，二分求出最小所需名额，
    提示调大上限后重算。

## 2. 目录结构

```
app/
  certutil.py     # PEM 解析、并集合并、openssl verify 封装
  planner.py      # 状态建模、BFS 求解、无解诊断
  app.py          # Flask 路由（/、/api/plan、/api/sample、/api/summaries）
  templates/      # 单页界面（原生 JS，无前端构建）
  static/         # 样式
scripts/
  generate_samples.py  # 生成两套独立 PKI 的演示证书
samples/          # 已生成的样例（根/中间/各副本链/根包/sample.json）
tests/            # pytest：求解器 25 项 + API 11 项（共 36 项）
Dockerfile, docker-compose.yml
```

## 3. 启动方式

### Docker Compose（推荐）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

镜像内已安装 openssl，并在启动时确保 `samples/` 样例存在；含健康检查。

### 本地直接运行

```bash
pip install -r requirements.txt
python scripts/generate_samples.py samples   # 已随仓库生成，可重复执行
flask --app app.app run --host 0.0.0.0 --port 8000
```

## 4. 网页试跑流程

1. 打开页面后样例自动载入（3 个副本 × 3 批终端，默认过渡上限 3）；也可点
   “载入证书样例”重新载入。每个 PEM 输入框失焦后会显示解析概要（叶子 CN、
   SAN、链长 / 根包内证书数量）。
2. 点“求解变更顺序”，得到分步方案，每步附带动作后的状态快照与
   “本步核验 9/9 个组合全部通过”的核验证据，页面下方还有 6 列核验矩阵。
3. 试调用上限（勾选“启用 OpenSSL 调用上限”后填入次数，再点求解）：
   - 填 54（=3 副本 × 3 批次 × 6 组合，全部核验格数）→ 与不限次数相同，
     9 步最短方案确认，矩阵无未验格，预算条显示实际调用 54 次；
   - 填 48 → 提前停验：返回 `plan_unconfirmed`，仍列出同一条 9 步、每步
     全部通过的方案并注明“最短步数待定”，矩阵出现 6 个“？”未验格；
   - 填 4 → 现状阶段即用尽，返回 `pending`（待核），实际调用恰为 4 次；
   - 上限改 0、调用上限填 50 → 仍确认“名额不足，至少需要 3 批同时过渡”，
     且实际调用（50 次）少于不启用上限时的 54 次。
4. 试无解场景：
   - 把上限改成 0 → 提示“过渡名额不足，至少需要 3 个批次同时过渡”；
   - 把某批的“新根证书包”替换成旧根包内容 → 提示硬无解并列出 9 个失败配对
     及 `unable to get local issuer certificate`（启用调用上限时验到首个
     失败即停，矩阵其余格保持未验）；
   - 把某个副本域名改成证书 SAN 之外的名字 → 提示 `hostname mismatch`
     （并附叶子实际 SAN）。

## 5. 实测结果

环境：Python 3.11 + OpenSSL 3.0.22，`pytest tests/` 共 **36 项全部通过**
（25 项求解器逻辑 + 11 项 Flask API），覆盖：

- 旧链仅被旧根信任、新链仅被新根信任、并集同时信任两者、域名不匹配必失败；
- 合法场景求出 9 步方案并逐步回放，验证每步只动一个对象、过渡名额不超限、
  每步全部核验通过、终态全部为新；
- L=0 多批次场景判为名额不足并求出最小名额 3，调到最小名额后可解；
- 新根包错放、现状即坏、SAN 不匹配均判硬无解且明细正确；
- 非法 PEM、空字段、非法上限、空表单均返回 400/抛错；
- 调用上限专项：不限次数时每格恰好调用一次（54 格 = 54 次）；预算永不
  超限且未验格不入缓存；现状阶段用尽判待核；`plan_unconfirmed` 方案每步
  全通过且放开预算后步数一致；预算增大时 `pending → plan_unconfirmed →
  plan` 收敛；硬无解验到失败即提前停验；名额二分时遇未验格只返回稳妥
  下界（桩验证，不把未验证名额计入下界）；非法预算（0/负数/非整数）拒绝。

HTTP 端到端冒烟（真实 Flask 服务）返回：

| 场景 | status | 关键输出 |
| --- | --- | --- |
| 默认样例（L=3，不启用上限） | `plan` | 9 步，每步 9/9 核验通过，实际调用 54 次 |
| 调用上限 48 | `plan_unconfirmed` | 9 步方案照列、最短步数待定，调用 48 次、6 个未验格 |
| 调用上限 4 | `pending` | 现状阶段用尽，调用恰 4 次、50 个未验格 |
| L=0 + 调用上限 50 | `insufficient_quota` | `min_required=3`，提前停验（50 < 54） |
| L=0 + 调用上限 30 | `pending` | 已用 30 次、24 个未验格，结论可能改判 |
| 新根包错放为旧根 + 上限 20 | `hard_infeasible` | 验到失败即停，18 次调用、9 个目标态失败项 |
| 预算 0 / 负数 / 非整数 | HTTP 400 | 明确错误提示 |

另用 jsdom 对渲染后的真实页面做 DOM 行为验证（13 项断言）：勾选启用/禁用
预算输入框、请求体按勾选情况携带/省略 `verify_budget`、待核与未确认方案
的 banner、预算条实际调用次数、矩阵通过/失败/未验三态渲染均符合预期；
页面内联脚本通过 `node --check` 语法检查。

另用 openssl CLI 直测样例链（旧包验旧链、并集包验新链、错误主机名拒绝）均符合预期。

## 6. 约束与余项

- 本机沙箱无 docker CLI，**Docker Compose 配置未在本机构建验证**；Dockerfile
  仅依据 python:3.11-slim 常规行为编写（显式 apt 安装 openssl、gunicorn 启动），
  请在有 Docker 的环境执行 `docker compose up --build` 复核。
- 证书核验通过每次请求临时文件调用 openssl 子进程完成；输入规模上限
  4×4，缓存按“副本 × 链 × 批次 × 根包”组合去重，每格每次请求最多调用
  一次，全量核验最多 4×4×6=96 次（默认 3×3 样例为 54 次），实测秒级
  返回，未做高并发压测；启用调用上限时实际次数不超过页面设定值。
- 工具只做离线顺序规划与核验，不连接任何真实服务、不保存录入内容
  （数据仅存在于浏览器与单次请求内存中）。
- 样例私钥仅用于本地生成演示证书，随生成过程只在 `samples/` 保留证书
  （脚本会在内存生成密钥，不落盘私钥文件）；请勿把样例证书用于任何真实环境。
- 证书链约定：叶子证书在前、中间 CA 依次在后的 PEM 拼接；根证书不放链文件，
  只放终端根包。
